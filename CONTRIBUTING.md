# Contributing

Thanks for helping out. These notes keep the team's work easy to follow.

## Branches

Create one short-lived branch per task and name it after the work:

- `feature/short-description` for new work
- `fix/short-description` for corrections
- `docs/short-description` for documentation

Pull `main` before you start so your branch begins from the latest work.

## Commit messages

- Start with a short summary written as an instruction, such as "Add setup notes".
- Keep the summary under about 50 characters.
- Leave a blank line before any longer explanation.
- If you paired with a teammate, credit them with a `Co-authored-by:` trailer.

## Pull requests

1. Push your branch and open a pull request against `main`.
2. Describe what changed and why.
3. Ask a teammate to take a look.
4. Merge once it's approved, then delete the branch.

## Asking for help

Open an issue and describe what you tried and what happened. Include any error
message in full, since the details usually point to the cause.

## Being a good teammate

- Say early if you're stuck or running late.
- Keep reviews kind and specific.
- Don't commit passwords, tokens or other secrets.
